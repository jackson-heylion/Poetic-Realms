# 馆藏整理与分类规则（v1）

## 目标与范围

策展对象不只名篇，而是**能被空间、光照、天气、声音、运动或建筑表现的具体文学意象**。收录诗、词、曲、乐府及景物描写浓厚的文、赋；体裁必须准确，不能把《滕王阁序》《岳阳楼记》误标为律诗。

每个作品保留稳定 `id`；标题、作者、时代、体裁与摘句独立字段。相同标题可通过作者/序号区分。现阶段未录全诗，不得在页面上显示“全文”。内容统一为 Unicode 简体录入，异文可单独记录，不用简繁自动转换替代版本校勘。

## 多维分类

- **朝代 / 时段**：先秦、两汉、魏晋、南北朝、唐、宋、元、明、清（朝代归属遇争议须补考据）。
- **体裁**：诗、词、曲、古体/乐府、文。例：《忆江南》为词，《天净沙·秋思》为曲。
- **景观意象（可多选）**：山川、江河、湖泊、瀑布、海景、江南、田园、村落、边塞、沙漠、古城、楼阁、古桥、庭院、古道、峡谷、溪涧、池塘、花木、荷花、飞鸟、雪景、风浪、云雾、雨雾、落日、日出、月夜、星空、节庆、历史遗址等。
- **难度**：H1–H5，评估场景表现与工程复杂度，不是诗歌文学评分。
- **制作状态**：available（待制作）、prototype（可体验原型）、published（验收发布）；Issue 领取状态另由 GitHub 实时管理。
- **校勘状态**：待校勘、已校勘。不得在没有准确、可复查来源时改为已校勘。

## 文本校勘最小流程

1. 核作者、篇名、时代和文体；区别诗作与同名组诗中的具体编号。
2. 对照有明确版本信息的古籍/权威整理本记录字形、断句、异文；必要时保留繁体底本。
3. 确认摘句来自该篇，排查网络误引、改写和张冠李戴。
4. 记录来源书目/卷次/页码或稳定链接、版本选择与校勘者；之后才将 `textReview` 改为已校勘。
5. 地点应拆成“可考地望”“传统解释”“艺术化推断”。如欧阳修《采桑子》之西湖应明确是颍州西湖，苏轼诗中西湖才是杭州西湖。苏轼赤壁文学地望，不等同三国赤壁战场。

## JSON 约定

目录为 `data/poems.json`，首层 `schemaVersion` + `poems`。每条记录包含 `id`、`title`、`author`、`dynasty`、`form`、`excerpt`、`categories[]`、`hardness`、`visualBrief`、`textReview`、`sceneStatus`、`scenePath`、`model`、`tools[]`、`issueNumber`。未来新增地理与来源字段应保持兼容并在 schema 版本中体现，禁止把 AI 自行猜测的坐标直接当作可靠数据。

## 推荐数据策略

大规模诗词库（如 `chinese-poetry/chinese-poetry`）用于**候选发现**，不是无条件全部发布到前端。先去重、筛出“可视化意象”和可教性，再人工抽样与逐首校勘。移动端不应一次加载几十万条，未来大库需要预生成分片静态搜索索引或后台服务。
