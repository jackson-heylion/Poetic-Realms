## 踩坑记录
- **山被裁掉**：远山仰角超过相机垂直半 FOV（46°/2=23°）时整层看不见。山高与距离要按 `atan(h/d) < 12°` 配，或压低机位。
- **ShaderMaterial + InstancedMesh**：`gl_InstanceID` 在 three 默认 GLSL1 下不可用（编译失败），改用 `InstancedBufferAttribute` 传相位；`instanceMatrix` 由 three 自动注入，可直接乘。
- **virtual-time 截图不可信**：`--virtual-time-budget` 下 rAF 与真实计时不一致，加载幕不消失、页面停在首帧。要装 playwright-core 驱动本机 Chrome，真实等 8 秒再截。
- **草/菊全黑**：低角度逆光时 MeshLambertMaterial 的 DoubleSide 草叶背光全黑，需补 emissive。
- **poems.json 追加**：用 `json.load` + `json.dumps(indent=2, ensure_ascii=False)` 回写只会顺带修正原有的错误缩进，diff 干净。
- 人物朝向：局部 -z 是脸的方向，`rotation.y=θ` 后前向是 `(-sinθ, -cosθ)`，0.7 左右才朝向 +z 一侧的相机。

## 本轮踩坑（重要，可复用）
- **`#include <tonemapping_pars_fragment>` / `<colorspace_pars_fragment>` 不要自己写**：three r152+ 已自动前缀进每个片元着色器，重复 include 会函数重定义 → fragment 编译失败、画面全黑。只需在结尾 include 非 pars 的 `<tonemapping_fragment>` / `<colorspace_fragment>`。
- **ShaderMaterial 的 fog 不自动生效**：`fog: true` 只加 define，`vFogDepth` 要在顶点着色器自己算，否则片元里声明了 varying 但顶点没写 → 链接失败。干脆自己按 `smoothstep(near, far, length(cameraPosition - vWorld))` 算。
- **贴图只画了圆 → 别用球体**：月面这种"画布上只有一个圆盘"的贴图，贴到 SphereGeometry 上，圆外的透明区按黑 RGB 渲染，会把月亮切出直边。用 Sprite / 面向相机的 Plane。
- **大尺寸半透明 Plane 必留矩形接缝**：天空中任何 600+ 宽的云片，即使贴图 alpha 边缘为 0，也会在地平线上留一条横贯画面的直缝。`destination-in` 四边做法有效但常常仍有可察觉的边界，最省事的是干脆不要云片。
- **"亮带"幻象**：连续几个截图里我以为是亮带，用 `gl.readPixels` 纵向扫描才发现像素值几乎恒定（8,20,26 → 8,20,31）。真正的观感来源是旁边纯黑（0,0,0）的剪影把过渡衬得像一条亮线。**判断画面问题先取像素值，别只靠看图**。
- **`InstancedMesh.count` 可以做 LOD**：一条实例化网格按距离排序填充，降档时改 count 即可，不用重建。远中景单独一条网格常驻，避免降档时出现"稻田尽头"的硬边。
- **Playwright 版本与浏览器缓存要对上**：`~/.npm/_npx/*/node_modules/playwright` 有好几个版本，1.64.1 要 chromium-1248 但缓存只有 1234；改用 `channel: "chrome"` 直接驱动本机 Chrome，顺带拿到真 GPU（ANGLE Metal）的帧率。

- 关键教训：
  - **`String.replace` 的替换串会解释 `$&`/`$'`**，把压缩版 three.js 内联进 HTML 时会把脚本标签插进库代码中间（`ht=$&!!s...`）。用 `replace(needle, () => block)` 规避。
  - **WebGL 里 2D 云图铺在等高云层上，斜视会出现地毯状摩尔纹**；换 Canvas 生成的无缝云图 + mipmap 后消失，帧率也从 14→90（Intel UHD 630，1440×900）。
  - 远处岸线用「树冠带 + 岸脚雾带」比单棵低模树可信得多；单棵树的棒棒糖轮廓一眼假。
  - 竖屏要单独调 fov（62°）与机位偏移，否则 48° 垂直视野在 390×844 会把船切成一半。
- 实测：1440×900 DPR1 高画质 48–52 FPS（120 draw calls，含平面反射）；390×844 DPR2 中画质 60 FPS（设备模拟，非真机）。
